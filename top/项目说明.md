项目位于 `E:\Phd\temperature\sam3\top`。输入是一段按时间排列的俯拍鱼类图片。跟踪模块给每帧中的鱼分配 ID 和轮廓，行为模块沿用这些 ID，测量每条鱼游了多远、游得多快、摆尾多少次每秒，以及鱼头朝向哪里。

### 1. 先获得分割结果，再计算行为

在 Windows PowerShell 中执行。第一次处理新的一组图片时按顺序运行两行。已有对应的 `output\tracking` 且其中 `run_info.json` 的 `status` 为 `complete` 时，直接执行第二行。

```powershell
& "D:\Anaconda\envs\sam3\python.exe" "E:\Phd\temperature\sam3\top\tracker\run_sam3.py"
& "D:\Anaconda\envs\sam3\python.exe" "E:\Phd\temperature\sam3\top\main.py"
```

跟踪脚本顶部的 `IMAGE_DIR` 默认为 `E:\Phd\temperature\sam3\000000`，`CHECKPOINT` 指向 `E:\Phd\temperature\sam3\top\tracker\models\sam3.pt`。`FPS` 默认为 30 帧/秒，应与这批图片的采样率对应。`MAX_FRAMES = 0` 表示处理全部图片。SAM3 跟踪使用 CUDA，已有掩膜的行为分析可以直接读取分割结果。

### 2. 每次选一个速度步长

打开 `E:\Phd\temperature\sam3\top\behavior\speed.py`，找到顶部这一行，填一个正整数并保存。单独运行 `speed.py` 和运行 `main.py` 都读取这一处设置，两种运动单位采用同一个步长。

```python
FRAME_STEP = 1
```

| 设置 | 某条鱼从原帧 0 开始出现时，依次测量的区间 |
|---|---|
| `1`（默认） | 0→1、1→2、2→3，测量每对相邻帧 |
| `5` | 0→5、5→10、10→15。第一个完整窗口含第 0 至第 5 帧，共 6 张图 |
| 其他正整数 `N` | 从该鱼首次出现帧 `A` 开始，依次测量 `A→A+N`、`A+N→A+2N` |

步长只影响运动区间。中间各帧仍参与跟踪、几何提取和质量检查，摆尾及朝向仍按原帧计算。改成 `5` 后，运行 `main.py` 即可同时刷新两个单位的结果。固定目录保留最近一次运行的数据。需要跨步长保存实验结果时，可在重算前自行复制要保留的结果，或在 Python 调用时指定不同的绝对输出路径。

### 3. 单独运行一种行为分析

以下命令按需要选择。它们和 `main.py` 共用对应的输出目录。输入、判头提示和视频开关分别由实际启动的入口顶部 `SEGMENTATION_DIR`、`HEAD_HINTS` 和 `SAVE_VIDEO` 控制，速度步长始终取上面的公共设置。运行 `speed.py` 会同时得到像素和 BL 两种单位的结果，`SAVE_VIDEO=True` 时请求两个单位的视频。

```powershell
& "D:\Anaconda\envs\sam3\python.exe" "E:\Phd\temperature\sam3\top\behavior\speed.py"
& "D:\Anaconda\envs\sam3\python.exe" "E:\Phd\temperature\sam3\top\behavior\tail.py"
& "D:\Anaconda\envs\sam3\python.exe" "E:\Phd\temperature\sam3\top\behavior\towards.py"
```

单独运行只重算所选模块。它会撤下上次 `main.py` 写出的两份综合文件，防止把上次的综合数值当作本次结果。再次运行 `main.py` 就会重建综合文件并使三个目录对应同一次分析。重新跟踪一组图片后，也需运行行为入口来刷新指标。

## 三、像素与 BL 速度字段

图像原点在左上角，x 向右，y 向下。鱼体位置取完整分割区域的质心。标准输入提供采集时间时使用真实时间差，否则根据原帧号和帧率算时间。本项目跟踪器优先用整段图片名中有效且递增的 `_t` 秒数归零，整段缺少合格时间戳时统一按 `frame/FPS`。

设一个有效窗口首尾质心的差为 `(dx,dy)`，时长为 `dt`。**无符号距离** `d = √(dx²+dy²)`，区间速率为 `d/dt`。首末帧头向单位向量求和并归一化，得到这个区间用来判前后的方向。位移沿此方向的投影为负且超出数值容差时，有符号距离为 `−d`，其余为 `+d`。有符号速度等于有符号距离除以 `dt`。

例如鱼头向左，向右 4 px 并向上 3 px 得 `−5 px`，向左 4 px 并向上 3 px 得 `+5 px`，纯向上 3 px 得 `+3 px`。若首末相隔 0.1 秒，第一种情形的速度为 `−50 px/s`。若该鱼参考体长是 100 px，同一行就是 `−0.05 BL`、`−0.5 BL/s`。

**参考体长** `L` 是同一 ID 在本批次全部几何有效、体长有限且大于零的帧中，头端到尾端中轴弧长的中位数。一条鱼在整批内使用自己的固定 `L`。距离和速度分别用像素值除以 `L`，位置坐标和面积仍用像素及像素平方。即使某条鱼没有可用体长也保留记录，其 BL 运动量留空。

一个完整窗口包括两端之间每个原帧。距离取首末质心的直线距离，中间帧用于质量检查。轨迹弯曲时，步长 5 的一次端点距离可以小于同段 5 次相邻距离之和。首帧和末尾不足整步的窗口保留占位行。遇到缺帧沿用原采样起点，完全没有该鱼观测的空窗口不展开。

### 3. 如何理解无效窗口

| quality_reason | 中文含义 |
|---|---|
| 空 | 无符号和有符号运动均通过检查。 |
| `first_observation` | 首次观测，尚无前一区间。 |
| `incomplete_window` | 末尾不足一个完整步长。 |
| `frame_gap` | 起点、终点或中间某帧缺少该鱼的记录。 |
| `invalid_centroid` | 窗口中至少一帧缺少有限的质心位置。 |
| `invalid_time_interval` | 时间缺失、非有限或相邻时间没有递增。 |
| `invalid_mask_area` | 至少一帧的面积缺失、非有限或不大于零。 |
| `mask_area_jump` | 相邻面积中较大值除以较小值，超过默认 1.5 的阈值。 |
| `head_axis_invalid` | 某帧的头向几何无效，原因见 quality_detail。 |
| `invalid_head_vector` | 头轴向量缺失、非有限或长度近零。 |
| `head_axis_jump` | 相邻帧头向变化超过默认 90°。 |
| `endpoint_head_axis_cancellation` | 首末头向相抵，无法给区间定义平均朝前方向。 |

速度 CSV 的无效区间测量通常为空。累计列可以延续上一个合格窗口的和。在整段无有效区间时，累加初值或汇总总距离可能是 0，应按相应有效标记解读。若 `distance_valid=1` 而 `direction_valid=0`，仍可用该窗口的无符号运动量。

## 四、摆尾字段

在每帧掩膜中取鱼体主体，对轮廓做保持连通性的细化。程序沿骨架选择端点间的主路径，延伸两端，重采样和平滑为 51 个中轴点。通过两端附近的体宽差、同一 ID 近期的有效头向或首次判头提示确定头尾。头端排在点 0，尾端排在点 50。沿中轴从头到尾的 10%～48% 拟合头轴，65%～95% 拟合尾轴。两根轴都朝头侧，因此直鱼的夹角约为 0°。正负表示轴间弯曲方向。

## 六、Python 调用与标准格式

从已完成的本地分割目录分析，或把外部系统的标准分割批次直接传入函数。一次调用处理同视频、同顶部视角的一批数据。速度需要完整窗口，摆尾频率需要连续周期，BL 的参考体长取自本批。分开多次调用时，每次独立计算。

```python
import sys
sys.path.insert(0, r"E:\Phd\temperature\sam3\top")
from main import analyze_behavior, analyze_segmentation

# 默认使用 speed.py 中的 FRAME_STEP。省略 output_dir 时仅返回数值。
result = analyze_segmentation(r"E:\Phd\temperature\sam3\top\output\tracking")

# 已有标准分割变量 standard_data 时，可选用这个入口。
# frame_step=5 只覆盖这次调用，同时作用于像素与 BL。
# result = analyze_behavior(standard_data, frame_step=5)

valid = [item for item in result["data"] if item["status"] == "ok"]
```

两个入口都可传 `output_dir`（绝对路径）写出文件，传 `save_video=True` 请求叠加视频。直接运行 `main.py` 会使用脚本顶部的固定输出目录和视频开关。首次判头有可靠人工依据时，可传 `head_hints={0: "left"}` 等提示，含义为 ID 0 首次定向时鱼头向左。

**标准输入** 的外层为 `{"data":[...]}`，每条记录是一帧的一条鱼。`track_id`、`frame_id` 是跨帧跟踪 ID 和原帧号。`segmentation.size` 为 `[高,宽]`，`counts` 为按列从上到下再向右、从背景开始交替记录的像素游程。`video_info` 可携带视频标识 `video_id`、帧率 `fps`、采集秒数 `timestamp_seconds` 和原图绝对路径 `image_path`。`view_info` 使用 `top`，`category_id` 对鱼通常为 1，`model_info` 描述来源。可选 `area`、`bbox` 分别为像素面积和 `[左,上,宽,高]`。几何算法会以解码掩膜复算面积和质心。同一个 ID 在同一帧只允许一条记录。

**标准返回值** 的外层也为 `{"data":[...]}`。每条记录的 `track_id`、`frame_id` 标识鱼和归属帧，`behavior_indicator` 是指标名，`behavior_value` 是数值，`unit` 是单位。`frame_range` 保存本指标实际涉及的帧号，运动项额外写 `frame_step`。汇总项列出相应有效区间的证据帧，没有有效区间时记录已有帧。BL 项还带参考体长、样本数和 `body_length_valid`。`status` 可为 `ok`、`insufficient_frames`（所需帧或周期不足）、`invalid`（其他质量问题），后两种配 `reason` 和数值占位 0。统计时先筛 `status=ok`，这样可保留真正的零速度。

| `behavior_indicator` | 对应指标 | `unit` |
|---|---|---|
| `position_x`、`position_y` | 掩膜质心的横、纵坐标 | `pixel` |
| `heading_tilt`、`tail_angle` | 对水平线的倾角、头尾轴有符号夹角 | `degree` |
| `tail_beat_frequency` | 单个连续片段的摆尾频率 | `Hz` |
| `speed`、`velocity` | 本区间无符号速率、有符号速度 | `pixel/s` 或 `BL/s` |
| `step_distance`、`signed_distance` | 本区间无符号距离、有符号距离 | `pixel` 或 `BL` |
| `total_distance`、`total_signed_distance` | 全批无符号总距离、有符号累计距离 | `pixel` 或 `BL` |
| `mean_speed`、`mean_velocity` | 全批无符号、有符号平均速度 | `pixel/s` 或 `BL/s` |

CSV 用同一行的像素列和 BL 列对应两种单位。标准返回值则由每条记录的 `behavior_value` 保存一个数值、`unit` 指明其单位。同一条鱼、同一帧可以有多个指标，同一个运动指标又可有两种单位。读标准结果时用 `track_id`、`frame_id`、`behavior_indicator`、`unit` 以及运动项的 `frame_step` 一起定位记录。
